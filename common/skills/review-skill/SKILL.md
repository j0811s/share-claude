# Review Skill

スキルを **その時点の Claude Code 公式ドキュメント** と照合し、根拠付きの修正候補を挙げる。
記憶している推奨ではなく、毎回取得したドキュメントの記述だけを根拠にする。

**このスキルではファイルを編集しない。** 修正候補を提示し、適用はユーザーの指示を待つ。

## 1. 対象の特定

- 引数がスキル名なら `.claude/skills/<name>/SKILL.md` → `~/.claude/skills/<name>/SKILL.md` の順に探す。引数が無ければ `.claude/skills/*/SKILL.md` を一覧して聞く。
- 対象ディレクトリ内の全ファイル（SKILL.md・参照ファイル・scripts）を読む。
- `.claude/skills/` が share-claude から配布されている場合（コミット履歴や README で判別）、修正はソース側（`~/github/share-claude/{common,project/<name>}/skills/`）で行う旨を報告に含める。

## 2. 公式ドキュメントの取得（毎回必須）

WebFetch で以下を取得する。前回の会話やキャッシュした知識で代用しない。

| ドキュメント | URL | 確認する観点 |
|---|---|---|
| Claude Code Skills | https://code.claude.com/docs/en/skills | frontmatter フィールド一覧・文字数制限・起動制御・引数・動的コンテキスト・allowed-tools |
| Skill authoring best practices | https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices | 命名・description の書き方・簡潔さ・段階的開示・ワークフロー・アンチパターン・末尾チェックリスト |

- ページが長く途中で切れた場合は `offset` を指定して最後まで読む。
- 取得に失敗した URL は、報告冒頭に「未確認」と明記する。その観点の指摘は出さない。
- ページ内で、上記以外の関連する公式ページへのリンクが必要になった場合は、それも取得する。

## 3. 機械的チェック

```bash
wc -l <SKILL.md>                       # 本文行数
sed -n '/^---$/,/^---$/p' <SKILL.md>   # frontmatter
```

取得したドキュメントに書かれた制限値と照合する：frontmatter のフィールド名が実在するか、`name` の文字種・長さ、`description`（+ `when_to_use`）の文字数、本文の行数、参照ファイルの深さ（SKILL.md から1階層か）、Windows 形式パス、`!` コマンドが失敗時にスキル全体を中断しないか。

## 4. 内容のレビュー

取得したドキュメントの各推奨について、対象スキルが満たしているかを判定する。特に：

- description が「何をするか」と「いつ使うか」を具体的なトリガー語で含むか
- Claude が既に知っていることを説明していないか（簡潔さ）
- 自由度（high / medium / low）が操作の危うさに合っているか
- 複数ステップの手順に、明確な順序・検証ループ・停止点があるか
- 用語の一貫性、時間依存の記述、選択肢の出しすぎ
- `argument-hint` / `disable-model-invocation` / `allowed-tools` など、使うべきなのに未使用のフィールド

## 5. 報告

次の形式で出力する。

```markdown
## レビュー対象
<パス>（ソース: <share-claude のパス or 同上>）

## 参照した公式ドキュメント
- <URL> — 取得成功 / 未確認

## 修正候補

### 1. [Must|Should|Could] <一行の要約>
- 箇所: `<file>:<line>`
- 現状: <該当箇所の引用>
- 根拠: <URL>#<セクション> 「<ドキュメントの該当記述。原文引用、取れなければ要旨>」
- 修正案:
  ```diff
  - 旧
  + 新
  ```

## 公式推奨と異なるが維持してよい点
- <プロジェクト規約（例: 日本語での記述）など、意図的な逸脱とその理由>

## 適合している点
- <主要な推奨のうち満たしているもの、簡潔に>
```

| 重要度 | 基準 |
|---|---|
| Must | ドキュメント上の制約違反（文字数・文字種・存在しないフィールド等）、またはスキルが正しく起動・動作しない原因になるもの |
| Should | ベストプラクティスからの明確な逸脱で、起動精度・遵守率・トークン効率に影響するもの |
| Could | 改善の余地があるが、現状でも問題なく機能するもの |

今回取得したドキュメントの記述で裏付けられない指摘（一般論・個人的な好み）は、修正候補に含めない。最後に、どの候補を適用するかユーザーに聞く。

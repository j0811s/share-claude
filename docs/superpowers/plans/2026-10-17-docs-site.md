# ドキュメントサイト（Astro Starlight）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `common/` と `project/<name>/` から「各プロジェクトに配布される結果」を自動で読み取り、プロジェクト単位の案内サイトを GitHub Pages に公開する。

**Architecture:** Python の `deployer/docs_data.py` が既存の重ね合わせ規則と `merge_settings` を使ってプロジェクトごとの配布結果を JSON にする。`site/scripts/generate-pages.mjs` がその JSON から Starlight の Markdown ページを `site/src/content/docs/<project>/` に生成し（gitignore）、`astro build` で静的サイトにする。GitHub Actions が PR で検証し、main への push で Pages にデプロイする。

**Tech Stack:** Python 3.9 標準ライブラリ / unittest、Node 24、Astro 7.4 系、@astrojs/starlight 0.42 系、`node:test`、GitHub Actions、`gh api`

**Spec:** `docs/superpowers/specs/2026-10-17-docs-site-design.md`

## Global Constraints

- Python 側は 3.9 標準ライブラリのみ。テストは `python3 -m unittest discover test`
- `Path.resolve()` を新規コードで使わない（`bin/` の既存 sys.path 挿入行は踏襲してよい）
- `deployer` の配布挙動（`build_plan` の結果）を変えない。既存テストは全て通ったままにする
- サイトは日本語のみ。URL は `https://j0811s.github.io/share-claude/`（Astro `site: 'https://j0811s.github.io'`, `base: '/share-claude'`）
- GitHub リンクは `https://github.com/j0811s/share-claude/blob/main/<リポジトリ相対パス>`
- 「共通」= common 由来、「専用」= project 由来。同名スキルは project が勝つ。hooks / permissions は common の settings.json に同一要素があれば「共通」
- スキル本文・references は表示しない
- `curl` / `wget` は使わない（ユーザーの禁止コマンド）。公開確認は `gh` かブラウザ MCP で行う
- main への push と GitHub 設定変更はユーザーに確認してから行う

## Review Focus

- frontmatter が無い・`description` が無い SKILL.md → ディレクトリ名で一覧に出て、概要は「（説明なし）」。ビルドは落ちない（Task 1, 3 にテスト）
- description に `|`・改行・`"`・`:` を含む → 表が崩れず、ページの frontmatter も壊れない（Task 3 にテスト）
- settings.json が common/project のどちらにも無い、hooks や permissions が無いプロジェクト → 各ページに「なし」と出る（Task 2, 3 にテスト）
- common と project に同名スキル → 1件だけ、origin は project（Task 1 にテスト）
- hooks の command が `hooks/` 配下のスクリプトを指さない（例: `npx foo`）→ script は null、command をそのまま表示（Task 2 にテスト）

ページ内容（Markdown、frontmatter の文字列は `JSON.stringify` で書いて YAML として安全にする。表セル内の `|` は `\|`、改行は空白に置換）:
- `index.md`（title: プロジェクト名、`sidebar.order: 0`, label「概要」）: スキル一覧表「呼び方 | できること | 区分」。呼び方は `` `/name argumentHint` ``（hint 無しは `/name`）でスキルページへリンク、区分は「共通 / 専用」＋ manualOnly なら「・手動のみ」。description が null なら「（説明なし）」。続けて hooks・禁止/許可へのリンク、CLAUDE.md（あれば）と rules（1件以上あれば）への GitHub リンク
- `skills/<skill>.md`（title: スキル名）: 要点カード（Starlight の `:::note` かリスト）で「呼び方」「できること」「区分」「Claude が自動で使うか（manualOnly なら『いいえ（手動で呼んだときだけ）』）」「ソース（GitHub リンク）」
- `hooks.md`（title「自動で動くもの」, order 90）: 表「タイミング | 内容 | 区分」。タイミングは `PreToolUse`→「ツール実行前」、`PostToolUse`→「ツール実行後」、他はイベント名そのまま。matcher があれば `` `Edit|Write` の`` を前置（`|` はエスケープ）。内容は script があれば説明（無ければ「（説明なし）」）＋スクリプトへのリンク、無ければ command をコード表示。0件なら「なし」
- `permissions.md`（title「禁止・許可」, order 91）: 「禁止」「実行前に確認」「確認なしで実行」の3節、各節に「ルール | 区分」の表。0件の節は「なし」

`astro.config.mjs`: `title: 'share-claude'`、`defaultLocale: 'root'`, `locales: { root: { label: '日本語', lang: 'ja' } }`、sidebar は `[{ label: 'はじめに', link: '/' }, ...projects.map(p => ({ label: p.name, autogenerate: { directory: p.name } }))]`（projects は `src/generated/docs-data.json` を `fs` で読む）。`social` に GitHub リンク。

`index.mdx`（はじめに）: サイトの見方（左のプロジェクトを開く）、スキルの呼び方（`/スキル名 引数`、手動のみの意味）、共通と専用の意味、設定の追加はこのリポジトリへの PR で行うこと。
